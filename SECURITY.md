# Security Policy

## Supported Versions

Only the latest release is supported with security updates. There are no backported fixes to older versions.

| Version | Supported |
|---------|-----------|
| Latest  | Yes       |
| Older   | No        |

### Submission Requirements

Your report **must** include:

1. **Exact configuration** used when the issue was discovered (OpenBao version, plugin version, OS, Go version)
2. **Step-by-step replication process** with sufficient detail to reproduce the vulnerability
3. **Your GPG public key** so we can respond securely

### What Will Not Be Accepted

Reports that are clearly generated by AI/LLM tools will not be acknowledged or responded to. We require genuine, human-verified security research with reproducible findings.

### Response Timeline

- **Acknowledgment of receipt:** 48 to 96 hours for submissions that meet the above requirements
- **Fix window:** After acknowledgment, we will correspond to arrange either a 60-day or 90-day fix window depending on severity and complexity
- **Disclosure delay:** After a fix is published, there will be an additional delay before public disclosure of the vulnerability to give users time to update

### Scope

The following are in scope for security reports:

- Authentication or authorization bypasses
- Cryptographic weaknesses in key generation, signing, encryption, or decryption
- Key material exposure or leakage
- Session hijacking or cross-user data access
- Denial of service via resource exhaustion (memory, CPU, storage)
- Input validation failures leading to unexpected behavior

The following are **out of scope**:

- Issues in OpenBao itself (report to the [OpenBao project](https://github.com/openbao/openbao/security))
- Issues in upstream dependencies (report to the relevant project)
- Findings that require physical access to the server
- Social engineering attacks

## Responsible Disclosure

We ask that you:

- Give us reasonable time to address the vulnerability before public disclosure
- Do not access or modify other users' data
- Do not degrade the service for other users
- Act in good faith to avoid privacy violations, data destruction, or service disruption
